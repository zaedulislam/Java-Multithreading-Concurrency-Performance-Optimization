# Critical Section

In this tutorial we will continue our discussion about the concurrency challenges we encountered while sharing objects between threads. And after we formalize the problem, we will explore the first solution to that problem.
Let's quickly recall the problem we discussed in the last tutorial. The problem we had with our simplified e-commerce inventory counter was that we had two threads sharing a single counter. Both threads were reading and modifying that counter, and those operations were not atomic.

![](https://github.com/zaedulislam/Java-Multithreading-Concurrency-Performance-Optimization/blob/main/images/image_6.1.png)

## Critical Sections
The problem, however, is a broad problem. Generally speaking, we would like to perform a set of operations in such a way that they will all appear as a single atomic operation, and no two threads can be performing those operations simultaneously.

![](https://github.com/zaedulislam/Java-Multithreading-Concurrency-Performance-Optimization/blob/main/images/image_6.2.png)


Let's call this section of code that we must protect from concurrent execution a critical section, and surround that critical section with an entry point and an exit point.

![](https://github.com/zaedulislam/Java-Multithreading-Concurrency-Performance-Optimization/blob/main/images/image_6.3.png)

There is no thread currently executing the critical section. Then that thread can enter it and execute operations one, two and three.

![](https://github.com/zaedulislam/Java-Multithreading-Concurrency-Performance-Optimization/blob/main/images/image_6.4.png)

If another thread comes in and is trying to enter the critical section while there is a thread already in it, it will be denied access and it will be suspended until the first thread exits the critical section.

![](https://github.com/zaedulislam/Java-Multithreading-Concurrency-Performance-Optimization/blob/main/images/image_6.5.png)


Once the first thread crosses the exit point of the critical section, the second thread can enter the critical section and perform all the operations inside it. This way, we can really achieve atomicity for any number of distinct operations without worrying about concurrency issues.

![](https://github.com/zaedulislam/Java-Multithreading-Concurrency-Performance-Optimization/blob/main/images/image_6.6.png)


![](https://github.com/zaedulislam/Java-Multithreading-Concurrency-Performance-Optimization/blob/main/images/image_6.7.png)


Luckily for us, the JVM, with the support from the operating system and the hardware, provides us with multiple tools to guard the critical section against concurrent access by multiple threads. Let's point out that the concepts and principles are the same everywhere. So what we're going to learn now, we will be able to find in other languages, but may mean a slightly different flavor or API.
