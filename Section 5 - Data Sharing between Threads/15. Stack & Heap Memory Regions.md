# Stack

Each stack region belongs to a particular thread


### What is the Stack?
- Memory region where
  - Methods are called/executed
  - Whenever we pass an argument to a function, it is passed on to the Stack
  - All the local variables are also stored on the Stack at any given moment
  - Each thread may be executing a different line of code or method. That's why we can think of the Stack and the instruction pointer as the overral state of each thread's execution.
    > Stack + Instruction Pointer = State of each thread's execution.

 ### Stack's Properties
 - All the variables passed on the Stack belong to a particular thread and other threads have no access to them
 - The Stack is allocated statically when a thread is created
 - The Stack's size is fixed, relatively small (Platform specific) and can not change in runtime
 - If our calling hierarchy is too deep, then we may get an ```StackOverflow``` Exception (Risky with recursive calls)

# Heap
- Memory region where
  - The heap is a shared memory region that belongs to the process
  - All the threads share whatever data is located on the heap and can access and allocate objects on the heap at any moment
    - What's allocated on the heap?
    > - All objects are stored in the heap. Basically, that's anything that we can allocate using the ```new``` operator that include objects of Java building classes, such as ```Strings```, Object collections as well as objects of classes, we define
    > - Everything in an object is also obviously stored on the heap. No matter if it's a primitive member or an object by itself
    > - Finally, ```static``` variables are also located on the heap that's because static variables are actually members of the class object associated with that class
  - The heap is managed and governed by the Java virtual machines garbage collector
  - Objects - stay on the heap as long as there is at least one reference to them and their garbage collected sometime after all the references to that object are lost.
  - Member of Classes - member variables are tied to their parent objects and have the same life cycle as their parents
  - Static Variables - stay forever and remain untouched throughout the entire application's lifetime.
